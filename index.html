// Process

How I use AI to build faster — and still make the call myself

AI speeds up the parts that used to eat my time. It doesn't replace the parts that require actually knowing the system.

01
Frame the real constraints first
Before touching a tool, I write down what actually can't move — no internet dependency, no database, must run on legacy hardware. AI can't know these; only working inside the system does.
02
Research and prototype with AI, fast
I use tools like Perplexity for research and Poe/Claude for drafting code, UX copy, and early prototypes — cutting the time from idea to first working version.
Perplexity · Poe · Claude
03
Pressure-test against edge cases
AI-generated output gets checked against what I actually know about the environment — flaky LAN connections, legacy Windows machines, non-technical end users. This is where most "AI-built" tools fall apart, and where I don't let them.
04
Decide, ship, own it
The final call on architecture, scope, and tradeoffs is mine. AI is the accelerant, not the decision-maker.

LAN Terminal & File Explorer
